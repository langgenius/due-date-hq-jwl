# 给 Claude Code 的工作说明

DueDateHQ 小红书变更卡渲染器。吃 JSON,出 1080×1440 PNG。

先读 `README.md`,再读这份。README 说明**怎么用**,这份说明**哪些不能动、接下来做什么**。

---

## 0. 上下文

- 用户是 DueDateHQ 的 co-founder,产品是给美国 CPA 事务所用的报税截止日变更监控。
- 这套卡片投放在小红书,受众是在美华人会计师,**日更**。
- 卡片的全部价值是可信度。**图上任何一个数字错了,产品就废了。** 校验优先于美观。
- 图不是最终产物,数据管道才是。图只是管道的输出终端。

## 2. 不要动的东西

这些数值背后每一条都对应一个具体的失败版本。改之前先问用户。

| 规则                                           | 位置                         | 改了会怎样                                                                                         |
| ---------------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------- |
| 字号只有四级 + 数字两级                        | `card.css` `--s-*`           | 之前有 15/16/17/22/23 五个字号并排,语义不同但视觉无差别,层级塌掉                                   |
| CJK 标题 `letter-spacing: 0`                   | `.ddhq__h`                   | 负字距会让宋体细笔画粘连,这是"读不懂"的直接物理原因                                                |
| 标题字重 900                                   | `.ddhq__h`                   | 700 在 108px 下撑不住,整版发虚                                                                     |
| 标题两行 = 主语 + 谓语,必须带动词              | `title` 数组                 | 只有主语的标题("华盛顿 / 9 个县")读者必须往下看日期才知道发生了什么                                |
| 标题不写日期                                   | —                            | 同一个日期一张卡只能出现一次                                                                       |
| 新日期 94px,旧日期 40px                        | `--s-date-*`                 | 核心叙事是"一个死了一个活着",不能只靠删除线区分                                                    |
| 红色只表示"这是错的"                           | `--red`, `.ddhq--correction` | 延期是好消息,用红色会让第一秒的情绪读取和消息性质相反                                              |
| 柠檬绿是唯一亮色                               | `--lime`                     | 只用于来源层级标签和新日期高亮条,不要扩散                                                          |
| 日期块右移 `--step: 104px`                     | `.ddhq__lab`, `.ddhq__dates` | 拉回左对齐会让整版塌在一条轴上,失去阅读引导                                                        |
| 印章挂在 `.ddhq__base` / `.ddhq__titlewrap` 上 | `.ddhq__stamp`               | 改回写死的绝对偏移会随内容高度撞上文字。已经发生过两次:一次是提示块高度变化,一次是中英标题字号不同 |
| 英文写 `postponed` 不写 `extended`             | caption + payload            | extension 在 CPA 语境里特指 Form 4868,用错会立刻暴露不是圈内人                                     |
| LinkedIn 画布 1080×1350                        | `format: li`                 | 4:5 是 LinkedIn 竖图上限,3:4 会被裁                                                                |

**印章那条特别说明:** 它是事务所收件章的移植,不是 UI 徽章。旋转 -9°、不加纹理、
不写品牌名。正着放会立刻退化成一个普通角标。

## 3. 优先做这些

按顺序。

### 3.1 发布前校验(最高优先级,先于任何视觉工作)

生成图之前必须全部通过,任一失败则阻断发布。这些错误人工审是防不住的——
实际已经连着出过 `1140`/`1232` 不存在的表号、`4月5日` 不存在的截止日、
`12 天` 算错的倒计时。

1. `countdown_days == (deadline - publish_date).days`
2. `kind=delay` 时 `newDate > oldDate`;`kind=correction` 时两者必须不等
3. `noticeId` 的年份 == 公告发布年份
4. `forms` ⊆ 白名单 `{1040, 1040-SR, 1041, 1065, 1120, 1120-S, 990, 941, 940, 5500, 706, 709, 预缴}`,不接受自由文本
5. `oldDate` 命中该税种的法定截止日表
6. `map.counties` 全部解析出 FIPS,数量 == 标题里写的县数
7. FIPS 的州前缀 == 公告所属州
8. `noticeId` 在 irs.gov 可取到 200,且页面正文含该编号
9. `publish_date >= detected.date`
10. `detected.time` 必须带时区
11. `forms` / `scope` 来自结构化字段,**禁止**从公告正文自由文本抽取
12. 同一 `noticeId` 已发布过 → 强制 `kind=correction`,不得静默覆盖原文

第 8 和第 11 最重要:一条防转述失真,一条防同一份数据在图上和库里长出两个版本。

### 3.2 县名 → FIPS 解析

IRS 公告只给县名不给 FIPS。映射表在 `us-county-maps/index.json`。

**必须在入库时一次性解析成 FIPS 存下来,渲染时不再按名字匹配。**

已知陷阱,不处理会出错:

- 弗吉尼亚有独立市和同名县:Richmond city `51760` vs Richmond County `51159`
- 马里兰:Baltimore city `24510` vs Baltimore County `24005`
- 密苏里:St. Louis city `29510` vs St. Louis County `29189`
- 路易斯安那是 parish,阿拉斯加是 borough / census area

用 `namelsad` 字段区分,不要只看 `name`。

### 3.3 像素回归

改任何 CSS 后跑 `samples.json` + `stress.json`,和上次输出做 diff,超过阈值要人确认。

日更 + 模版自动填,没有这一层的话某次改动会静默毁掉某种状态的排版,
而那种状态可能几周才出现一次。`correction` 和 `pending` 尤其危险。

### 3.4 文案长度约束

`tip.body` 目前没有上限,超过一定字数会把上面的内容顶掉。
加进校验:按渲染后实测的行数卡,不要按字符数猜。

### 3.5 CJK 排版

两个已知问题,需要真实文案才测得出来:

- **标点避头尾**:长句在特定宽度下会把「,」「。」甩到行首。加 `line-break: strict`
  并实测。
- **中英混排间距**:「致电 IRS 灾害热线」这类现在靠人手打空格。应在渲染前
  自动插入,或用 `text-autospace`。

## 3.6 双平台

同一个 payload 出两张图,只改 `locale` 和 `format`。**不要维护两份数据。**

| 平台     | `format` | 画布            | `locale` | 标题字体           | 字号  |
| -------- | -------- | --------------- | -------- | ------------------ | ----- |
| 小红书   | `xhs`    | 1080×1440 (3:4) | `zh`     | 思源宋体 900       | 108px |
| LinkedIn | `li`     | 1080×1350 (4:5) | `en`     | Source Serif 4 700 | 76px  |

4:5 是 LinkedIn 竖图上限,3:4 会被裁。西文标题更长,所以降一档字号、
`--step` 收到 72px。西文可以用轻微负字距(-.015em),CJK 不行。

**英文术语强制表**,不得替换:

| 概念               | 用                      | 不要用                                |
| ------------------ | ----------------------- | ------------------------------------- |
| 灾害减免的日期变动 | `postponed`             | `extended`（那指 Form 4868 主动申请） |
| 覆盖范围           | `covered disaster area` | `affected area`                       |
| 适用人群           | `affected taxpayers`    | `eligible people`                     |
| 预缴               | `estimated payments`    | `prepayment`                          |

`postponed` / `extended` 这条最关键。LinkedIn 上的读者是本土 CPA,
用错这个词一眼看出不是圈内人,而产品卖的就是圈内可信度。

英文 caption 另有约束:无 emoji、hashtag 三个以内或不加、不放 URL
(LinkedIn 压制带外链的帖子,链接放评论区)、开头 140 字符内必须有钩子句。

## 4. 内容节奏

用户要日更,但变更不会每天有。**不要为了填空档而拔高无关紧要的变更**——
那比不发更伤可信度。

固定栏目轮转:

| 栏目     | 出现条件                | 用哪种 kind                          |
| -------- | ----------------------- | ------------------------------------ |
| 变更播报 | 有变更就插队,优先级最高 | delay / correction / pending / multi |
| 今日核查 | 无变更时的默认          | 待建,见下                            |
| 本周到期 | 每周一                  | 待建                                 |
| 一个坑   | 每周二、四              | 待建                                 |
| 上周回顾 | 每周五                  | 待建                                 |

**「今日核查」是最重要的一个,优先建。** 它把"今天没事发生"变成一条正面内容:
51 个辖区全绿 + 「0 变更,已核 51」。

这是审计 tick mark 体系里 `Ø`(检查了,确认无异常)的逻辑——**"没变"和"没查"
必须区分开,而证明自己每天都在查,是监控产品唯一的信任来源**。竞品做不出这个
栏目,因为他们没在查。

这条天然日更、天然不过期、天然复用同一套模版。

## 5. 正文 caption

图上的字不被搜索索引,关键词全靠 caption。每条必须包含:

- 完整县名列表(图上已经移除,caption 是它唯一的位置,也是主要 SEO 来源)
- 表格号、公告号、州名
- 实务提示原文
- 「本月已监测到 N 次变更」+ 主页引导(小红书图上不能点)

## 6. 已知未解决

- 只在 Chromium 验证过。导出走 PNG 所以影响有限,但若做网页版,
  Safari 的 `mix-blend-mode` 和 `feTurbulence` 表现不同。
- 字体从 Google Fonts 加载。**上生产必须自托管**:CI 里字体没下载完会静默
  fallback,图正常生成、不报错,但字体是错的。这类失败最难发现。
  渲染后加一步断言:检查标题实际解析到的 `font-family` 和 `font-weight`。
- `title` 只支持两行。出现「马萨诸塞州及以下市镇」这类超长主语时没有降级方案。
- 多州卡超过 12 行会截断为「另有 N 个辖区」,尚未和用户确认这个上限合理。

---

## 7. 判断原则

拿不准时按这个顺序:

1. **准确 > 美观。** 数字错了,再好看的卡也是负资产。
2. **可被指认 > 看起来对。** 每个数值都要能说出为什么是这个值。
3. **系统 > 单张。** 不要为某一条公告特调版式,要让模版容纳它。
4. **不确定就问用户,不要猜。** 尤其涉及税务实务内容的准确性。
